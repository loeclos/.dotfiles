# NixOS Dotfiles

This machine is declarative. Host config lives in `~/.dotfiles` (flake root,
user `loeclos`). Read `AGENTS.md` first; it is the binding, detailed guide.
Never edit `/etc/nixos/` directly — edit the flake, verify, then rebuild.

## Hosts and flake

- `flake.nix` exports `nixosConfigurations.{desktop,laptop,live-desktop,live-laptop}` via `lib/mkHost.nix`.
- `desktop` is the NVIDIA daily driver (early KMS, `useOSProber`, `/mnt/ssd`, desktop-only CUDA Ollama); `laptop` enables `power-profiles-daemon`.
- `live-{desktop,laptop}` are minimal GNOME + Calamares installer ISOs with recovery tools and `withHome = false`; the flake is embedded at `/iso/dotfiles`. They must not import `modules/system` or generated `hosts/hardware/*.nix` scans.
- Hardware scans are generated by `nixos-generate-config`; never hand-edit them. `hosts/common.nix` owns shared timezone, locale, NetworkManager, and user groups.

## Where changes go

- `lib/theme.nix` is the single source for shared palette, fonts, cursor, and display settings.
- `lib/apps.nix` is the single source for browser, terminal, agent, file-manager, and editor choices and their catalogs. Consumers get `apps` through `specialArgs` / `extraSpecialArgs`; use the catalog's `command`, `packageAttr`, `flakeInput`, or `desktopId` rather than hardcoding app choices.
- Host quirks go in `hosts/<name>.nix`; shared system features in `modules/system/`; graphical/home features in `modules/home/desktop/`, GUI apps in `modules/home/apps/`, CLI tools in `modules/home/cli/`, and home packages/XDG integration in `modules/home/system/`.
- In-repo derivations and shell scripts go in `packages/builds/` or `packages/scripts/`, then are exposed through the single overlay in `packages/default.nix` as `pkgs.<name>`. Auto-imported module folders need no manifest edits.
- Put assets in `assets/` and refer to them via `repoRoot + "/assets/..."`, not relative `../../` paths. Wallpapers use one-word lowercase filenames.

## Shell aliases and dev shells

`modules/system/shell.nix` sets `environment.shellAliases`, so `ls` / `ll` / `la`, `edit`, `shell`, and `dots` are available in Bash and Zsh. Home Manager also defines the eza aliases for interactive Bash inside `nix-shell` (which skips `/etc/bashrc`). Zsh provides:

- `rbld [target]` — sudo rebuild + switch, defaults to the hostname; accepts `laptop`, `.#laptop`, or `#laptop`, sends a notification, and preserves the exit code. For interactive use, prefer this alias.
- `update [input]` — no argument updates all flake inputs (run from the flake root); an input argument updates that input in `~/.dotfiles`.

These are interactive-user aliases, not instructions to use `sudo` from an agent. There are no project `shell.nix` files: use `nix-shell -p <pkg>` or `nix shell nixpkgs#<pkg>` for ad-hoc environments. Do not add a `shell.nix` unless requested.

## Privilege escalation

Interactive users use `sudo`. Agents (including OpenCode) use `pkexec` for commands that need root; it displays the GUI prompt from `hyprpolkitagent`. The required wrapper is enabled in `modules/system/security/polkit.nix`, and the agent is configured in `modules/home/desktop/hyprpolkitagent.nix`.

- Always use the absolute flake path with `pkexec`, e.g. `pkexec nixos-rebuild switch --flake /home/loeclos/.dotfiles#desktop`. Relative `.` resolves to `/root` under `pkexec`.
- The GUI prompt reappears every time by design. A dismissed prompt reporting `Not authorized / This incident has been reported` is expected.
- Never add a wheel-to-`YES` polkit rule or `NOPASSWD` sudo rule to suppress prompts.
- Run ordinary Nix commands (`nix flake check`, `nix fmt`, `nix flake update`, `nix build`) as the user; reserve `pkexec` for root-required operations.

## Edit, verify, rebuild

1. Make the smallest change in the existing category. Follow `AGENTS.md` for naming, package/module conventions, auto-import, and its documentation rules: update both `README.md` and `AGENTS.md` for each repo change, keep the README timestamp current, and keep AGENTS guidance aligned with the architecture.
2. Verify evaluation before rebuilding:
   ```bash
   nix flake check --no-build
   nix fmt # optional; nixfmt-rfc-style
   ```
3. For an agent, use `pkexec` and an absolute flake path for privileged builds or switches, for example:
   ```bash
   pkexec nixos-rebuild build --flake /home/loeclos/.dotfiles#desktop --dry-run
   pkexec nixos-rebuild switch --flake /home/loeclos/.dotfiles#desktop
   ```
   Interactive users can use `sudo nixos-rebuild ...` or `rbld desktop`.
4. Build an ISO without switching with `nix build .#nixosConfigurations.live-desktop.config.system.build.isoImage` (or `live-laptop`). On a booted ISO, `sudo install-nix` is the guided installer; the manual fallback is `sudo nixos-install --flake /iso/dotfiles#desktop` (or `#laptop`). Do not install via Calamares.

## Current desktop details to preserve

- Ghostty Home Manager configuration is conditional on `terminalName == "ghostty"`; other terminal selections currently get the package but not equivalent terminal-specific configuration. TUI agents launch inside the selected terminal.
- Wallpaper selection uses `walt` with the Hyprpaper backend; `SUPER+SHIFT+W` opens it in the selected terminal. The boot fallback is `road.png`.
- Screenshots use `watershot` through `pkgs.screenshot`, bound to bare `Print`. It saves the selected region under `~/Pictures/Screenshots` and explicitly pipes the PNG to `wl-copy`; do not restore the old multi-key screenshot binds or re-add `hyprshot` / `grim` / `slurp` as the screenshot toolchain.
- `SUPER+S` launches Spotify. The screensaver toggle is `SUPER+CTRL+S`; hypridle starts it after 10 minutes idle and quits it on activity.

For detailed architecture, pitfalls, and verification requirements, follow `AGENTS.md` and `README.md` in the repository.
